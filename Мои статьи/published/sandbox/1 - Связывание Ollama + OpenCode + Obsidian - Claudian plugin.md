# Интеграция Ollama, OpenCode и Obsidian (Плагин Claudian)

Эта заметка описывает процесс настройки связки локального LLM-движка, оркестратора и интерфейса в Obsidian для работы с продвинутыми моделями (в частности, `gemma4:31b-cloud`).

## 🎯 Цель
Организация бесплатного (или квотированного) доступа к мощным моделям через локальный бэкенд с интеграцией в рабочую среду Obsidian.

## 🛠 Окружение
| Компонент        | Версия / Среда                               | Роль                           |
| :--------------- | :------------------------------------------- | :----------------------------- |
| **ОС**           | Windows 10 + WSL2 (Ubuntu)                   | Основная среда                 |
| **LLM Engine**   | [Ollama](https://ollama.com/) (в WSL2)       | Запуск и управление моделями   |
| **Orchestrator** | [OpenCode](https://opencode.ai/) (Win + WSL) | Связующее звено (Bridge)       |
| **IDE/Notes**    | [Obsidian](https://obsidian.md/)             | Интерфейс взаимодействия       |
| **Plugin**       | Claudian                                     | Интеграция OpenCode в Obsidian |

## 🚀 Пошаговая настройка

### 1. Установка и запуск Ollama
Для обеспечения стабильной сетевой связности между WSL и Windows-хостом рекомендуется устанавливать Ollama внутри **WSL2 (Ubuntu)**.

> [!WARNING] Важно
> Не запускайте версию Ollama для Windows и версию для WSL одновременно, так как они будут конфликтовать за порт `11434`.

Ollama под Windows прекрасно работает, но когда надо состыковать, например VS Code в режиме работы внутри WSL с Ollama на хосте Windows нужны дополнительные настройки, а под Windows 10 связка между WSL хостом требует дополнительных приседаний или местами вообще не работает.
### 2. Настройка OpenCode
Чтобы OpenCode (как в Windows, так и в WSL) мог "видеть" Ollama, запущенную внутри WSL, необходимо настроить конфигурационный файл.

**Путь к конфигу:** `~/.config/opencode/opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai",
  "model": "ollama/gemma4:31b-cloud",
  "provider": {
    "ollama": {
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1",
        "apiKey": "ollama"
      },
      "models": {
        "gemma4:31b-cloud": {
          "name": "gemma4:31b-cloud",
          "limit": {
            "context": 131072,
            "output": 16384
          }
        }
      }	  
    }
  }
}
```

### 3. Решение проблемы авторизации (Ошибка 401)
При использовании облачных моделей через Ollama (например, `gemma4:31b-cloud`) может возникнуть ошибка `Unauthorized (401)`. Для её устранения необходимо авторизовать свою учетную запись.

Выполните команду в терминале WSL:
```bash
ollama signin
# перейдите по ссылке и авторизуйте приложение
```
После этого OpenCode получит доступ к моделям.

### 4. Интеграция с Obsidian (Плагин Claudian)
Плагин Claudian в Obsidian под Windows автоматически обнаруживает установленный в системе OpenCode. После этого настроенный провайдер Ollama и модель `gemma4:31b-cloud` становятся доступны для использования в заметках.

## 💡 Дополнительные рекомендации
* **Полный переезд на WSL:** Если сетевые задержки или сложности с портами сохраняются, стоит рассмотреть возможность установки Obsidian непосредственно внутри WSL (через X-сервер или WSLg), чтобы вся цепочка инструментов работала в едином Linux-окружении.
