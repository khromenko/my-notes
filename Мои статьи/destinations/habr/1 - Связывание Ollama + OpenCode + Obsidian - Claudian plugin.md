# Подключение  AI-стека в свою базу знаний Obsidian (Claudian + OpenCode  + Ollama)

В данной статье я разберу, как построить работающую связку локального LLM-движка, оркестратора и интерфейса в Obsidian. Это позволит использовать продвинутые модели, такие как `gemma4:31b-cloud`, прямо в вашем рабочем пространстве для заметок/базе знаний.
При этом модель `gemma4:31b-cloud` работает в облаке Ollama (не требуется установка локально, поэтому не загружает ваши ресурсы) и не требует оплаты (довольно большая бесплатная квота).
Информация актуальна для РФ, т.к. без всяких VPN и прочих сложностей позволяет настроить и апробировать AI-инструменты в своей работе с Obsidian.

## 🎯 Цель и архитектура
Основная задача — организовать доступ и использование мощных моделей через локальный бэкенд с интеграцией в Obsidian (вообще без оплаты).

**Стек технологий:**
- **ОС:** Windows 10 + WSL2 (Ubuntu) — обеспечивает лучшую совместимость с Linux-инструментами.
- **LLM Engine:**  [Ollama](https://ollama.com/) (запущен в WSL2) — отвечает за загрузку и исполнение моделей.
- **Orchestrator:** [OpenCode](https://opencode.ai/) — выступает в роли моста (Bridge) между движком и интерфейсом.
- **Интерфейс:** [Obsidian](https://obsidian.md/) + Плагин Claudian — предоставляет удобную среду для взаимодействия с AI.

## 🚀 Пошаговая настройка

### 1. Установка и запуск Ollama в WSL2
Для обеспечения стабильной сетевой связности между WSL и Windows-хостом настоятельно рекомендуется устанавливать Ollama именно внутри **WSL2**. 

> [!WARNING] Важный нюанс по портам
> Не запускайте версию Ollama для Windows и версию для WSL одновременно. Обе версии претендуют на порт `11434`, что приведет к конфликту.

Использование Ollama в WSL2 решает многие проблемы с сетевым взаимодействием, которые возникают при попытках соединить Windows-приложения с Linux-сервисами и наоборот.

### 2. Конфигурация OpenCode
Чтобы OpenCode мог взаимодействовать с Ollama, необходимо правильно настроить конфигурационный файл.

**Путь к конфигу:** `~/.config/opencode/opencode.jsonc`

Пример настройки для модели `gemma4:31b-cloud`:
```jsonc
{
  "$schema": "https://opencode.ai",
  "model": "ollama/gemma4:31b-cloud",
  "provider": {
    "ollama": {
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1",
        "apiKey": "ollama"
      },
      "models": {
        "gemma4:31b-cloud": {
          "name": "gemma4:31b-cloud",
          "limit": {
            "context": 131072,
            "output": 16384
          }
        }
      }
    }
  }
}
```

При первичной настройке подключения к облачным моделям через Ollama может возникнуть ошибка `Unauthorized (401)`. Это происходит из-за отсутствия авторизации в системе Ollama (необходимо предварительно выполнить регистрацию  в Ollama).

Для исправления выполните команду в терминале WSL:
```bash
ollama signin
```
Перейдите по появившейся ссылке, авторизуйте приложение, и доступ к моделям будет открыт.

Демонстрация как Opencode запускается в WSL Ubuntu и работает с локальной Ollama, при этом использует бесплатную облачную модель gemma4-31b-cloud.

### 4. Завершение интеграции в Obsidian
Установите плагин **Claudian** в Obsidian. Плагин автоматически обнаружит установленный OpenCode в системе. Теперь в настройках провайдера выберите Ollama и модель `gemma4:31b-cloud`.
