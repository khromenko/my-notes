# Интеграция Ollama, OpenCode и Obsidian: Создание мощного AI-стека с плагином Claudian

В данной статье мы разберем, как построить эффективную связку локального LLM-движка, оркестратора и интерфейса в Obsidian. Это позволит использовать продвинутые модели, такие как `gemma4:31b-cloud`, прямо в вашем рабочем пространстве для заметок.

## 🎯 Цель и архитектура
Основная задача — организовать доступ к мощным моделям через локальный бэкенд с глубокой интеграцией в Obsidian. 

**Стек технологий:**
- **ОС:** Windows 10 + WSL2 (Ubuntu) — обеспечивает лучшую совместимость с Linux-инструментами.
- **LLM Engine:** Ollama (запущен в WSL2) — отвечает за загрузку и исполнение моделей.
- **Orchestrator:** OpenCode — выступает в роли моста (Bridge) между движком и интерфейсом.
- **Интерфейс:** Obsidian + Плагин Claudian — предоставляет удобную среду для взаимодействия с AI.

## 🚀 Пошаговая настройка

### 1. Установка и запуск Ollama в WSL2
Для обеспечения стабильной сетевой связности между WSL и Windows-хостом настоятельно рекомендуется устанавливать Ollama именно внутри **WSL2**. 

> [!WARNING] Важный нюанс по портам
> Не запускайте версию Ollama для Windows и версию для WSL одновременно. Обе версии претендуют на порт `11434`, что приведет к конфликту.

Использование Ollama в WSL2 решает многие проблемы с сетевым взаимодействием, которые возникают при попытках соединить Windows-приложения с Linux-сервисами и наоборот.

### 2. Конфигурация OpenCode
Чтобы OpenCode мог взаимодействовать с Ollama, необходимо правильно настроить конфигурационный файл.

**Путь к конфигу:** `~/.config/opencode/opencode.jsonc`

Пример настройки для модели `gemma4:31b-cloud`:
```jsonc
{
  "$schema": "https://opencode.ai",
  "model": "ollama/gemma4:31b-cloud",
  "provider": {
    "ollama": {
      "name": "Ollama (local)",
      "options": {
        "baseURL": "http://localhost:11434/v1",
        "apiKey": "ollama"
      },
      "models": {
        "gemma4:31b-cloud": {
          "name": "gemma4:31b-cloud",
          "limit": {
            "context": 131072,
            "output": 16384
          }
        }
      }
    }
  }
}
```

### 3. Решение проблемы авторизации (Ошибка 401)
При работе с облачными моделями через Ollama часто возникает ошибка `Unauthorized (401)`. Это происходит из-за отсутствия авторизации в системе Ollama.

Для исправления выполните команду в терминале WSL:
```bash
ollama signin
```
Перейдите по появившейся ссылке, авторизуйте приложение, и доступ к моделям будет восстановлен.

### 4. Завершение интеграции в Obsidian
Установите плагин **Claudian** в Obsidian. Плагин автоматически обнаружит установленный OpenCode в системе. Теперь в настройках провайдера выберите Ollama и модель `gemma4:31b-cloud`.

## 💡 Рекомендации по оптимизации
Если вы сталкиваетесь с сетевыми задержками или сложностями с портами, рассмотрите возможность установки Obsidian непосредственно внутри WSL (через WSLg или X-сервер). Это позволит всей цепочке инструментов работать в едином Linux-окружении, исключая лишние прослойки сетевого взаимодействия между Windows и WSL.
